# 디지털 트윈 기반 자율 공기질 관리 로봇 차별화 방안 보고서 초안

## 1. 프로젝트 개요

본 프로젝트는 ROS 2 Jazzy 기반 TurtleBot3 Waffle 로봇에 미세먼지 센서(PMS7003), 릴레이 제어 팬, Navigation2, rosbridge, 웹 관제 대시보드를 결합한 이동형 공기정화 로봇 시스템이다. 로봇은 실내 공간을 이동하며 PM2.5 농도를 측정하고, 오염도가 높은 위치에서 정지하여 팬을 작동시킴으로써 국소적인 공기정화 작업을 수행한다.

기존 구현은 로봇의 이동, 미세먼지 측정, 팬 제어, 웹 UI 관제를 통합했다는 점에서 기본적인 시스템 구성은 갖추고 있다. 그러나 단순히 "로봇이 이동하면서 미세먼지를 측정하고 정화한다"는 수준에 머무를 경우, 기존 이동형 로봇 또는 공기청정기와 비교했을 때 기술적 차별성이 충분히 드러나지 않을 수 있다. 이에 본 보고서에서는 프로젝트의 차별성을 강화하기 위한 추가 기능으로 **디지털 트윈 기반 공기질 지도와 Utility 기반 정화 우선순위 결정 기능**을 제안한다.

## 2. 기존 시스템의 한계

현재 시스템은 로봇의 위치, 지도, 센서값, 수동/자동 제어 기능을 웹 UI에서 확인할 수 있다. 그러나 지도 표현은 주로 ROS 점유격자 지도 형태에 가까워, 사용자가 공간 내 공기질 상태를 직관적으로 파악하기에는 한계가 있다.

또한 미세먼지 센서값이 단일 수치로만 표시될 경우, 다음과 같은 문제가 발생한다.

- 오염이 공간의 어느 위치에서 발생했는지 직관적으로 알기 어렵다.
- 로봇이 수집한 데이터가 공간 정보와 연결되어 보이지 않는다.
- 로봇이 왜 특정 위치로 이동하거나 정화하는지 판단 근거가 명확히 드러나지 않는다.
- 정화 전후의 변화가 시각적으로 표현되지 않아 성능 검증이 약하게 보일 수 있다.

따라서 본 프로젝트의 차별성을 강화하기 위해서는 센서값을 단순 표시하는 수준을 넘어, 로봇이 수집한 데이터를 공간 지도와 결합하고, 이를 기반으로 다음 행동을 결정하는 구조가 필요하다.

## 3. 제안하는 차별화 방향

본 프로젝트의 차별화 방향은 다음 한 문장으로 정리할 수 있다.

> 본 시스템은 이동형 공기청정 로봇을 넘어, 로봇이 수집한 PM2.5 데이터를 실내 지도 위에 실시간으로 누적하고, 오염 분포를 시각화하며, 고농도 구역을 우선 정화하는 디지털 트윈 기반 자율 공기질 관리 시스템이다.

이를 위해 다음 두 가지 기능을 핵심 차별화 요소로 추가한다.

1. **실시간 공기질 Heatmap 기반 디지털 트윈 지도**
2. **Utility 기반 고농도 구역 우선 정화 알고리즘**

두 기능은 독립적인 장식 요소가 아니라 서로 연결된다. 로봇은 실내를 이동하며 위치별 PM2.5 데이터를 수집하고, 웹 대시보드는 이를 지도 위에 Heatmap 형태로 표시한다. 이후 시스템은 오염도, 이동 거리, 최근 방문 여부, 미탐색 구역 여부 등을 종합한 Utility 점수를 계산하여 다음 정화 목표를 선택한다.

## 4. 기능 1: 실시간 공기질 Heatmap 기반 디지털 트윈 지도

### 4.1 기능 설명

로봇이 이동하면서 측정한 PM2.5 값을 로봇의 현재 위치와 함께 저장한다. 각 데이터는 다음과 같은 형태로 누적된다.

```text
(x 좌표, y 좌표, PM2.5 농도, 측정 시간)
```

웹 대시보드는 이 데이터를 지도 위에 표시한다. 단순한 점 표시에서 끝나는 것이 아니라, PM2.5 농도에 따라 색을 다르게 표현하여 실내 공간의 공기질 분포를 Heatmap으로 보여준다.

예상 색상 체계는 다음과 같다.

| 상태 | PM2.5 농도 예시 | 지도 색상 |
| --- | ---: | --- |
| 좋음 | 낮음 | 파랑 또는 초록 |
| 보통 | 중간 | 노랑 |
| 나쁨 | 높음 | 주황 또는 빨강 |
| 정화 중 | 팬 작동 위치 | 파란 테두리 또는 강조 표시 |

측정하지 않은 구역은 주변 측정값을 바탕으로 보간하여 부드러운 오염 분포로 표현한다. 초기 구현에서는 복잡한 모델 대신 거리 기반 보간 방식인 IDW(Inverse Distance Weighting)를 적용할 수 있다. 이를 통해 로봇이 직접 지나가지 않은 공간도 주변 측정값을 기반으로 추정된 공기질 상태를 확인할 수 있다.

### 4.2 차별성

이 기능은 기존의 단순 센서 표시 방식과 비교하여 다음과 같은 차별성을 가진다.

- PM2.5 수치를 공간 정보와 결합하여 실내 공기질 지도를 생성한다.
- 로봇이 측정한 데이터를 디지털 트윈 지도에 실시간 반영한다.
- 사용자가 오염 구역과 청정 구역을 한눈에 파악할 수 있다.
- 삼성/LG 공기청정기 앱처럼 직관적인 공기질 시각화를 제공하면서, 로봇 이동 데이터까지 함께 반영한다.

즉, 본 프로젝트는 단순히 "현재 미세먼지 농도"를 보여주는 것이 아니라, "실내 어느 위치가 오염되었는지"를 보여주는 시스템으로 확장된다.

## 5. 기능 2: Utility 기반 고농도 구역 우선 정화 알고리즘

### 5.1 기능 설명

로봇이 모든 구역을 정해진 순서로 순회하는 방식은 단순하지만, 실제 공기질 관리 관점에서는 비효율적일 수 있다. 오염도가 높은 구역이 이미 확인되었음에도 정해진 경로를 계속 따라가는 것은 정화 반응 속도를 떨어뜨린다.

이를 개선하기 위해 후보 위치별 Utility 점수를 계산하고, 점수가 가장 높은 위치를 다음 정화 목표로 선택한다.

기본 수식은 다음과 같이 설계할 수 있다.

```text
Utility = 오염도 점수 - 이동 거리 비용 - 최근 방문 패널티 + 미탐색 구역 보너스
```

각 항목의 의미는 다음과 같다.

| 항목 | 의미 |
| --- | --- |
| 오염도 점수 | PM2.5 농도가 높을수록 증가 |
| 이동 거리 비용 | 현재 위치에서 멀수록 감소 |
| 최근 방문 패널티 | 이미 최근에 방문한 구역이면 감소 |
| 미탐색 구역 보너스 | 아직 측정하지 않은 구역이면 증가 |

이 방식은 단순히 가장 가까운 곳으로 이동하거나 정해진 순서대로 이동하는 것이 아니라, 공기질 상태와 로봇 이동 비용을 함께 고려하여 다음 행동을 결정한다.

### 5.2 웹 UI 표시 방식

해당 알고리즘이 단순히 내부적으로만 동작하면 발표 시 차별성이 잘 드러나지 않을 수 있다. 따라서 웹 지도 위에 다음 정보를 함께 표시한다.

- 후보 정화 위치
- 각 후보 위치의 Utility 점수
- 선택된 다음 목표 지점
- 선택 이유
- 현재 로봇 위치와 목표 위치 간 경로

예를 들어 웹 대시보드에는 다음과 같은 형태로 표시할 수 있다.

```text
다음 정화 목표: Zone C
Utility: 92점
선택 이유: 오염도 높음 + 이동 거리 짧음 + 최근 미방문 구역
```

이를 통해 심사위원은 로봇이 임의로 움직이는 것이 아니라, 실시간 센서 데이터와 지도 정보를 기반으로 다음 행동을 결정한다는 점을 직관적으로 이해할 수 있다.

## 6. 기능 3: 정화 전후 효과 시각화

차별성을 더욱 강화하기 위해 정화 작업 전후의 PM2.5 값을 비교하여 표시한다. 로봇이 고농도 위치에 도착하면 팬을 작동하기 직전의 PM2.5 값을 저장하고, 일정 시간 정화 후 다시 측정한 값을 비교한다.

예시는 다음과 같다.

```text
Before: 72 ug/m3
After: 41 ug/m3
Reduction: -43%
```

이 기능은 단순히 팬을 켰다는 동작 표시를 넘어, 실제 정화 효과를 수치로 제시한다는 점에서 중요하다. 발표 시에는 특정 위치에서 오염 수치가 감소하는 모습을 대시보드에서 보여줌으로써 시스템의 실효성을 강조할 수 있다.

## 7. 구현 가능성

제안 기능은 현재 시스템 구조를 크게 변경하지 않고 확장할 수 있다.

현재 사용 가능한 주요 데이터 흐름은 다음과 같다.

| 데이터 | 현재 또는 추가 토픽 | 활용 방식 |
| --- | --- | --- |
| 지도 | `/map_web` | 웹 지도 배경 표시 |
| 로봇 위치 | `/robot_pose_web` | 현재 위치, 이동 경로, 측정 위치 기록 |
| PM2.5 값 | `/pm25` | 현재 공기질, Heatmap, Utility 계산 |
| 팬 상태 | 릴레이 제어 상태 토픽 | 정화 중 표시, 전후 비교 |
| 목표 지점 | 추가 가능 | 다음 정화 목표 시각화 |

초기 구현은 웹 UI 내부에서 로봇 위치와 PM2.5 값을 결합하여 샘플을 저장하고 Heatmap을 그리는 방식으로 진행할 수 있다. 이후 구조를 고도화할 경우, 별도의 ROS 노드인 `air_quality_map_node.py`를 추가하여 공기질 샘플, Heatmap 데이터, 목표 위치, 정화 결과를 계산하고 웹 UI는 이를 구독하여 표시하는 구조로 확장할 수 있다.

권장 구조는 다음과 같다.

```text
PMS7003 센서
  -> /pm25

로봇 위치
  -> /robot_pose_web

공기질 지도 노드
  -> 위치 + PM2.5 샘플 누적
  -> Heatmap 계산
  -> Utility 기반 목표 선택

웹 대시보드
  -> 지도 표시
  -> Heatmap 표시
  -> 로봇 위치 표시
  -> 다음 정화 목표 및 정화 효과 표시
```

## 8. 기대 효과

본 차별화 기능을 추가하면 프로젝트는 다음과 같은 방향으로 발전한다.

첫째, 단순 이동형 공기청정 로봇에서 **실내 공기질을 지도화하는 디지털 트윈 시스템**으로 확장된다.

둘째, 로봇이 측정한 데이터를 기반으로 다음 정화 위치를 결정하므로 **센서 기반 자율 의사결정 기능**을 갖게 된다.

셋째, 웹 대시보드에서 Heatmap, 정화 목표, Utility 점수, 정화 전후 효과를 시각적으로 보여줄 수 있어 **발표 및 시연 효과**가 크게 향상된다.

넷째, 하드웨어를 추가하지 않고 기존 PMS7003 센서, 로봇 위치 정보, 웹 UI를 활용하므로 **구현 비용 대비 차별화 효과**가 크다.

## 9. 최종 차별성 정리

기존 주제가 다음과 같았다면,

```text
TurtleBot3 기반 이동형 공기청정 로봇
```

차별화 이후의 주제는 다음과 같이 정리할 수 있다.

```text
디지털 트윈 공기질 지도를 기반으로 고농도 구역을 판단하고 우선 정화하는 ROS 2 자율 공기질 관리 로봇
```

이 차별화 방향은 단순히 UI를 예쁘게 개선하는 것이 아니라, 로봇이 수집한 센서 데이터를 공간 정보와 결합하고, 이를 바탕으로 다음 행동을 결정하는 구조를 추가한다는 점에서 의미가 있다. 따라서 본 프로젝트는 공기청정 기능을 탑재한 이동 로봇을 넘어, 실내 환경 상태를 인식하고 판단하며 대응하는 지능형 환경 관리 로봇 시스템으로 발전할 수 있다.

## 10. 향후 구현 우선순위

구현은 다음 순서로 진행하는 것이 적절하다.

1. 웹 지도 디자인을 발표용 하이브리드 맵 형태로 개선
2. 로봇 위치와 PM2.5 값을 결합한 측정점 표시
3. 측정점 기반 Heatmap overlay 구현
4. 고농도 후보 구역 자동 선택
5. Utility 점수와 다음 정화 목표 표시
6. 정화 전후 PM2.5 변화율 표시

위 순서로 구현하면 중간 단계에서도 시각적으로 확인 가능한 결과물을 만들 수 있으며, 최종적으로는 공기질 지도 생성, 자율 정화 판단, 정화 효과 검증이 하나의 대시보드에서 연결되는 형태의 차별화된 시스템을 완성할 수 있다.
